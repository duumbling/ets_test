# ETS2 Navigator: подключение на Windows 10

Сайт: https://duumbling.github.io/ets_test/

Ник Steam, пароль Steam и Cloudflare для **локального подключения** не нужны. Для телефона ПК с игрой и смартфон должны находиться в одной домашней сети.

## 1. Проверка без игры

1. Установи Python 3.10+ с официального сайта: https://www.python.org/downloads/windows/
2. Скачай репозиторий **Code → Download ZIP**, распакуй и открой PowerShell в корне проекта.
3. Выполни:

   ```powershell
   py -m pip install -r client/requirements.txt
   py client/lan_bridge.py --demo
   ```

4. Консоль покажет **12-символьный код сеанса** и локальный адрес:
   - На том же ПК: `ws://127.0.0.1:8765`.
   - На телефоне: `ws://192.168.1.20:8765` (IP будет индивидуальным; возьми **тот, который напечатает программа**).
5. Открой https://duumbling.github.io/ets_test/ в последнем Chrome или Edge. Выбери «Локальная сеть — без облака», введи адрес и код, нажми «Подключить».
6. Если браузер запросит **Local Network Access / Доступ к локальной сети**, разреши. Должна появиться тестовая скорость и координаты.

**Пока используется демонстрационная карта:** маршрут на ней не совпадает с реальными дорогами ETS2, маркер машины по настоящим координатам не рисуется.

## 2. Реальная телеметрия игры

Для чтения данных ETS2 потребуется сторонний DLL-плагин [SCS Telemetry Hub](https://github.com/UncappingBadger/Badgers-SCS-Telemetry-Hub). Он работает через официальный SCS Telemetry SDK; исходники открыты, но мы не включаем непроверенный готовый DLL в репозиторий.

1. Собери или установи этот плагин по инструкции автора в папку ETS2 `bin\\win_x64\\plugins`.
2. Запусти ETS2 и загрузи профиль.
3. На игровом ПК открой `http://127.0.0.1:38471/snapshot`: должен отображаться JSON из игры.
4. Останови демонстрационный мост сочетанием `Ctrl+C` и запусти обычный:

   ```powershell
   py client/lan_bridge.py
   ```

5. На сайте введи новый код и адрес из консоли. Будут передаваться скорость и координаты грузовика.

## 3. Если не подключается

- На Windows разреши Python доступ в брандмауэре **только для частных сетей**.
- Телефон и ПК должны находиться в одной локальной сети; гостевой Wi-Fi с изоляцией клиентов не подходит.
- Сайт использует `https://`, мост — `ws://`. Современные Chrome/Edge умеют спрашивать разрешение для локальных WebSocket, но другие браузеры и старые версии могут блокировать такое соединение. В настройках сайта разреши Local Network Access.
- `127.0.0.1` на телефоне означает **сам телефон**, а не игровой ПК. Используй IP игрового ПК.
- «Ожидание ETS2» означает, что соединение с мостом есть, но он пока не получает телеметрию.
- `--demo` позволяет проверить передачу без плагина/игры.

## 4. Безопасность

Не перенаправляй порт 8765 на роутере в интернет. Соединение `ws://` в локальной сети не шифруется; пользуйся только доверенным домашним Wi-Fi. Код сеанса считай секретом. Мост принимает подключение лишь с нашего GitHub Pages и localhost для разработки.
