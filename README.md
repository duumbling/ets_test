# ETS2 Navigator — версия 0.2

Интерактивный сайт с планировщиком маршрутов для Euro Truck Simulator 2, который можно разместить на GitHub Pages. Есть также **опциональное** подключение живой телеметрии с ПК через персональный код, Cloudflare Worker (Durable Object) и плагин SCS Telemetry Hub.

> **Честное ограничение v0.1:** на сайте установлена **демонстрационная схема** городов и тестовых дорог. Это НЕ карта дорог ETS2 и НЕ маршрут из игры. Кнопки маршрутов работают по тестовому графу (алгоритм Дейкстры); реальные карты/дорожный граф/координаты грузовика на этой схеме **не отображаются совместно**. Дальше нужно построить и подключить настоящие картографические данные из своей копии ETS2.

## Уже реализовано

- Современный сайт на русском, адаптация для телефона и второго экрана.
- Выбор отправления, назначения, промежуточных остановок.
- Выбор пункта назначения кликом по карте, перемещение/масштаб, расчёт пути по рёбрам графа, сохранение плана в браузере.
- Экспорт маршрута в JSON.
- Подключение к серверу через случайный **12-символьный код**, без Steam и пароля.
- Отображение скорости и игровых координат ETS2 с плагина телеметрии (когда на ПК запущены мост, игра и плагин).
- Проект сайта автоматически публикуется из папки `site/` через GitHub Actions.

## Новое в v0.2: без облака и без Steam

Теперь сайт на [GitHub Pages](https://duumbling.github.io/ets_test/) поддерживает локальное подключение к ETS2 без аккаунта Cloudflare. Нужно запустить WebSocket-мост `client/lan_bridge.py` на игровом ПК и ввести на сайте случайный 12-символьный код из терминала. Браузер может запросить разрешение **Local Network Access**. В Chrome/Edge современных версий такие подключения поддерживаются.

**[Пошаговая инструкция для Windows 10](docs/START_WINDOWS.md)**

Минимальный тест без ETS2:

```powershell
py -m pip install -r client/requirements.txt
py client/lan_bridge.py --demo
```

Затем открой сайт, выбери «Локальная сеть», укажи `ws://127.0.0.1:8765` (на том же ПК) или адрес своего ПК в LAN (с телефона), введи код. Тестовая скорость и координаты должны обновляться.

**Обязательно:** это локальное `ws://` соединение без TLS, не публикуй порт 8765 в интернете. Для доступа снаружи сети остаётся опциональный Cloudflare Relay. Реальные данные игры требуют SCS Telemetry Hub, а настоящая дорожная карта пока отсутствует — все маршруты на сайте остаются демонстрационными.

## Структура

```text
site/                     статический сайт для GitHub Pages
  index.html              интерфейс
  app.js                  маршруты, карта, WebSocket клиент
  styles.css              оформление
  config.js               адрес сервера (после публикации)
  data/map.json           ТЕСТОВЫЙ граф, выдуманные координаты
relay/                    Cloudflare Worker + Durable Object WebSocket relay
  worker.js
  wrangler.toml
  package.json
client/                   программа-мост для Windows
  bridge.py               SCS Telemetry Hub (SSE) -> WSS relay
  requirements.txt
.github/workflows/pages.yml   автоматический GitHub Pages деплой
```

## Шаг 1: посмотреть сайт локально

Нужен Python (на Windows обычно `py`). В папке проекта:

```powershell
py -m http.server 8000 --directory site
```

Откройте `http://127.0.0.1:8000`. Карту можно трогать и строить тестовые маршруты **без ETS2**. Не открывайте `index.html` через `file://`: JavaScript не сможет прочитать JSON карты из-за ограничений браузера.

## Шаг 2: разместить на GitHub Pages

1. Создайте **пустой** репозиторий на GitHub, например `ets2-navigator`, выберите публичный (для бесплатного GitHub Pages).
2. Распакуйте этот ZIP, **загрузите все папки и файлы** в корень репозитория (включая скрытую `.github`).
3. В `Settings` → `Pages` → `Build and deployment` установите `Source: GitHub Actions`.
4. На вкладке `Actions` дождитесь успешной задачи `Deploy ETS2 Navigator to GitHub Pages`.
5. Адрес будет в форме `https://ВАШ_ЛОГИН.github.io/ets2-navigator/` (или в настройках Pages).

Для первой проверки подключения телеметрии к сайту перейдите к шагу 3. Без шагов 3–5 сайт с тестовой картой уже доступен.

## Шаг 3: развернуть сервер-посредник (для данных из игры)

Понадобится учётная запись Cloudflare и Node.js (для утилиты Wrangler). **GitHub Pages сам WebSocket-сервер не создаёт.**

В терминале в папке `relay/`:

```powershell
npm install
npx wrangler login
npx wrangler deploy
```

В конце команда выдаст HTTPS-адрес вида `https://ets2-navigator-relay.ВАШ-ПОДДОМЕН.workers.dev`.

В файле `site/config.js` замените пустую строку на WSS-адрес **вашего собственного** Worker:

```javascript
window.ETS2_NAV_CONFIG = {
  relayUrl: 'wss://ets2-navigator-relay.ВАШ-ПОДДОМЕН.workers.dev'
};
```

Закоммитьте изменение — GitHub Pages обновится автоматически. Вместо изменения файла можно ввести адрес WSS в «Настройки сервера» на сайте: браузер запомнит его локально на этом устройстве.

Cloudflare Durable Objects доступны на поддерживаемых тарифах, включая бесплатные квоты SQLite-backed Durable Objects, но проверьте актуальные лимиты и условия аккаунта. Данный Worker не хранит данные или Steam-профили в постоянной базе.

## Шаг 4: поставить официальный мост данных телеметрии

Нужен работающий в ETS2 плагин, который выдаёт данные через `http://127.0.0.1:38471/stream`.

Пример — открытый проект [UncappingBadger / Badgers-SCS-Telemetry-Hub](https://github.com/UncappingBadger/Badgers-SCS-Telemetry-Hub). Его документация объясняет сборку DLL и размещение в:

```text
<папка ETS2>/bin/win_x64/plugins/scs_telemetry_hub.dll
```

Сам DLL сюда **не включён**. Установите/соберите плагин по его собственным инструкциям. Затем запустите игру. В браузере на игровом компьютере адрес `http://127.0.0.1:38471/snapshot` должен вернуть JSON при работающем плагине. Если не возвращает, мост запустить пока не получится.

## Шаг 5: подключение на сайте

Установите Python-библиотеку и запустите наш мост на ПК с ETS2:

```powershell
py -m pip install -r client/requirements.txt
py client/bridge.py --relay wss://ets2-navigator-relay.ВАШ-ПОДДОМЕН.workers.dev
```

В терминале появится **КОД СЕАНСА** из 12 символов. Откройте сайт на телефоне, введите этот код и нажмите «Подключить». Скорость и X/Z поступят в браузер. Игра и компьютер должны оставаться включёнными; при закрытии терминала трансляция остановится.

### Проверка без ETS2

Можно проверить весь сетевой канал, ещё не устанавливая игровой плагин:

```powershell
py client/bridge.py --relay wss://ets2-navigator-relay.ВАШ-ПОДДОМЕН.workers.dev --demo
```

Это **искусственные** данные. Скорость и координаты на сайте начнут обновляться. Маркер грузовика пока не рисуется на демонстрационном графе: настоящие игровые координаты нельзя достоверно совместить с вымышленной картой.

## Безопасность

- **Ник Steam не используется**: он не является ключом доступа к живой телеметрии.
- 12-символьный случайный код выступает секретом подключения (приблизительно 60 бит энтропии). Не публикуйте его и не показывайте посторонним в трансляциях.
- Передача идёт через TLS (`wss://`). Реле получает только X/Z, скорость, направление и название игры. Никаких паролей, Steam-токенов или данных браузера не требуется.
- Для каждой игровой сессии генерируется новый код, если не указан `--code`.
- Данный MVP не предназначен для публичной массовой эксплуатации: в нём нет полноценной системы аккаунтов, rate limiting, защит от злоупотреблений и ограничений времени жизни комнат. Для публикации общедоступного сервиса эти функции надо добавить.

## Следующий этап: настоящая карта ETS2

Сейчас `site/data/map.json` содержит **вымышленные** точки с `coordinateSystem: "demo"`. В ETS2 мир использует собственные координаты X/Z. Для достоверного навигатора потребуется:

1. Извлечь дорожную сеть и координаты городов из своей законной установки игры. В качестве основы изучить [truckermudgeon/maps](https://github.com/truckermudgeon/maps): parser, generator, маршрутизацию и PMTiles.
2. Получить данные и преобразовать их в формат приложения. Дороги ETS2 не равны дорогам OpenStreetMap и не совпадают с обычными GPS-координатами.
3. Добавить подложку настоящей карты в MapLibre/PMTiles и быстрый роутинг по полноценному графу. Простейший алгоритм Дейкстры из v0.1 пригоден только для небольшого графа, не всей карты игры.
4. Для точного позиционирования грузовика применять **те же координаты**, что и в Telemetry SDK, и учитывать дополнения карты/ProMods.
5. Не публиковать исходные ресурсы игры или производные тайлы без проверки прав и разрешений правообладателя. Можно генерировать тайлы из локально установленной копии игры и хранить отдельно при соблюдении условий использования.

Эта версия — честный **технический фундамент**, а не готовый GPS с дорогами и направлениями поворота. Отображение точного маршрута и реальных дорог в ETS2 будет реализовано отдельным этапом.
