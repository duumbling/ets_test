## Alpha 1.0: готовая карта ETS2 без сканирования файлов игры

Исследованы сторонние готовые карты и дорожные графы. Сводка: [источники, версии, ограничения и права использования](docs/READY_MAP_SOURCES.md).

- **[Открыть готовую карту в нашем сайте](https://duumbling.github.io/ets_test/online-map.html):** скачай ETS2 `.pmtiles` из [релиза OpenHaul](https://github.com/NekoSuneProjects/OpenHaul/releases/tag/map-data) (около 22,6 МБ) и выбери его в браузере. Файлы `.scs` и инструменты сборки не нужны. Доступна карта дорог и городов; полнота DLC конкретной игровой версии пока не подтверждена.
- **Для маршрутов** можно дополнительно загрузить уже имеющийся `ets2-routepack.json`, но это приблизительная навигация по отдельному графу.
- Самый полный обнаруженный готовый GPS — [Truck Dash](https://trucksim-dash.com/ru/). Однако разработчик [запретил прямое использование его картографического хостинга сторонними сайтами](https://github.com/Nethercap/truck-companion#name-and-logo), а запрос от GitHub Actions получил HTTP 403. Используй официальное приложение Truck Dash, если нужны его готовые граф и визуальная карта без сканирования. Мы **не обходим это ограничение**.
- Старая страница ETS2 Navigator и сохранённые пользовательские файлы продолжают работать независимо.

## Новое в Alpha 0.9: значки объектов и исправленная карта перекрёстков

Обнови страницу сайта через **Ctrl + F5**. Если подробный слой уже сохранён в профиле, он загрузится автоматически; иначе повторно выбери тот же `ets2-city-detail.json.gz` на шаге 2. **Пересобирать архив не нужно.** Для полной инструкции см. [руководство](docs/DETAILED_CITY_MAP.md).

Для экспорта подробного слоя из **уже полученных игровых данных** (без повторного извлечения 1828 секторов):

```cmd

```

Нужны два новых файла `tools/build_city_detail.py` и `tools/ets2-nav-convert.ts` из репозитория. На ПК с установленным инструментарием появится `Downloads\ets2-city-detail.json.gz`. Загрузи его в новую секцию «Подробная карта улиц и развязок». Сами дороги отображаются по геометрии генератора, но некоторые перекрёстки могут отличаться от ETS2, а маршруты пока рассчитываются по упрощённому графу.

## Новое в Alpha 0.6: игровые объекты и маршруты до них

Навигатор теперь импортирует **POI из самой ETS2**: заправки, сервисы, стоянки, предприятия, дилеров, гаражи, кадровые агентства, паромы и другое. По ним можно искать и выбирать их в качестве пункта назначения. При приближении объекты появляются на карте; отображаются только попавшие в видимую область.

Самый быстрый способ обновить уже сформированную карту, если в кэше инструментов остались файлы `out/parser/europe-pois.json` и `out/europe-graph.json`:

```cmd
py tools\build_real_map.py --repack-only
```

Нужно обновить два скрипта в локальной папке: `tools/build_real_map.py` и `tools/create_ets2_routepack.py`. Старый JSON (без POI) продолжит работать, но для отображения заправок потребуется новый экспорт.

**Ограничение:** пока маршрут прокладывается к ближайшему дорожному узлу объекта, а не обязательно прямо ко входу или заправочной колонке. Точный расчёт движения внутри префабов игровых объектов будет отдельным этапом.

Подробнее: [объекты ETS2 и маршруты к ним](docs/POI_DESTINATIONS.md).

## Новое в Alpha 0.5: карты сохраняются в браузере

- **Достаточно загрузить JSON один раз.** Карта хранится в IndexedDB на текущем устройстве и автоматически открывается при следующем посещении GitHub Pages.
- **Несколько профилей:** можешь хранить карты для различных наборов DLC; выбор и удаление доступны на сайте. Для активных картографических модов автоматический экспорт пока не реализован.
- **Сборка двойным щелчком на Windows:** запусти `tools/build_map_windows.cmd` (потребуются Python, Git, Node.js 24+ и Visual Studio C++ Build Tools при первой сборке).
- **Вариант без DLC:** `tools/build_map_windows.cmd --base-only`.
- **Общий JSON в открытом GitHub пока не публикуем:** нужно проверить разрешения правообладателя на распространение извлечённых игровых данных.

См. [подробное руководство по картам и профилям](docs/MAP_PROFILES.md).

# ETS2 Navigator — версия 0.3

Интерактивный сайт с планировщиком маршрутов для Euro Truck Simulator 2, который можно разместить на GitHub Pages. Есть также **опциональное** подключение живой телеметрии с ПК через персональный код, Cloudflare Worker (Durable Object) и плагин SCS Telemetry Hub.

> **Ограничение без импорта:** на сайте установлена **демонстрационная схема** городов и тестовых дорог. Это НЕ карта дорог ETS2 и НЕ маршрут из игры. Кнопки маршрутов работают по тестовому графу (алгоритм Дейкстры); реальные карты/дорожный граф/координаты грузовика на этой схеме **не отображаются совместно**. Дальше нужно построить и подключить настоящие картографические данные из своей копии ETS2.

## Новое в v0.3: настоящая сеть дорог (после импорта файла ETS2)

Сайт [GitHub Pages](https://duumbling.github.io/ets_test/) умеет загружать `ets2-routepack.json`, отображать дороги и города в **игровых координатах**, вести маршрут по направленным связям и размещать маркер грузовика, если подключена настоящая телеметрия. Файл обрабатывается локально браузером. В репозитории **нет игровых карт**: пока пользователь не импортировал собственный файл, всё ещё показывается демо-схема.

Упрощённая сборка на Windows: `py tools/build_real_map.py` (нужны Git, Node.js 24+, Python и C++ Build Tools).

Полная инструкция: [Создание карты из ETS2](docs/REAL_MAP.md). Конвертер: `tools/create_ets2_routepack.py`; проверки маршрута и конвертера запускаются в CI при каждом деплое.

Важное ограничение: новая сеть — предварительная топологическая схема. Она не показывает точные изгибы всех дорог, не учитывает все ограничения поворотов и не передаёт маршрут в игровой GPS. Для полноценного визуального навигатора следующий этап — тайловая карта PMTiles + точный роутинг.

## Шаг 1: посмотреть сайт локально

Нужен Python (на Windows обычно `py`). В папке проекта:

```powershell
py -m http.server 8000 --directory site
```

Откройте `http://127.0.0.1:8000`. Карту можно трогать и строить тестовые маршруты **без ETS2**. Не открывайте `index.html` через `file://`: JavaScript не сможет прочитать JSON карты из-за ограничений браузера.

## Шаг 2: разместить на GitHub Pages

1. Создайте **пустой** репозиторий на GitHub, например `ets2-navigator`, выберите публичный (для бесплатного GitHub Pages).
2. Распакуйте этот ZIP, **загрузите все папки и файлы** в корень репозитория (включая скрытую `.github`).
3. В `Settings` → `Pages` → `Build and deployment` установите `Source: GitHub Actions`.
4. На вкладке `Actions` дождитесь успешной задачи `Deploy ETS2 Navigator to GitHub Pages`.
5. Адрес будет в форме `https://ВАШ_ЛОГИН.github.io/ets2-navigator/` (или в настройках Pages).

Для первой проверки подключения телеметрии к сайту перейдите к шагу 3. Без шагов 3–5 сайт с тестовой картой уже доступен.

## Рекомендуемый путь: без Cloudflare и без аккаунтов (локальная сеть)

Подробная инструкция для Windows 10 находится в [docs/START_WINDOWS.md](docs/START_WINDOWS.md).

1. Установить Python и зависимости: `py -m pip install -r client/requirements.txt`.
2. На игровом ПК установить SCS Telemetry Hub (это плагин DLL, который читает телеметрию через официальный SDK; в архив не входит). Затем запустить ETS2. Открыв `http://127.0.0.1:38471/snapshot` на игровом ПК, можно проверить подключение плагина.
3. Выполнить `py client/lan_bridge.py` на игровом ПК. Программа покажет код из 12 символов и адрес, например `ws://192.168.1.23:8765`.
4. Открыть `https://duumbling.github.io/ets_test/` в Chrome или Edge на том же ПК или телефоне, подключённом к той же Wi-Fi сети. Вверху выбрать **«Локальная сеть — без облака»**, вписать адрес и код, нажать **«Подключить»**.
5. Если браузер запросит доступ к локальной сети, разрешить. Если соединение не устанавливается, проверить брандмауэр Windows и то, что телефон и ПК в одной сети.

**Тест без игры:** `py client/lan_bridge.py --demo` — сайт будет получать вымышленные координаты и скорость. Маркер машины не появится на демонстрационной карте — она не использует координаты игры.

На Windows (и особенно на телефоне) сайт GitHub Pages открывается по HTTPS, а локальный мост по `ws://`; в новых Chromium-браузерах для такого подключения требуется разрешение Local Network Access. Старые версии и другие браузеры могут блокировать его. Локальный порт 8765 не следует открывать в Интернет через маршрутизатор. Код сеанса считай секретным.

Если нужен доступ **из другой сети**, используется альтернативный облачный путь ниже.

## Шаг 3: развернуть сервер-посредник (для данных из игры)

Понадобится учётная запись Cloudflare и Node.js (для утилиты Wrangler). **GitHub Pages сам WebSocket-сервер не создаёт.**

В терминале в папке `relay/`:

```powershell
npm install
npx wrangler login
npx wrangler deploy
```

В конце команда выдаст HTTPS-адрес вида `https://ets2-navigator-relay.ВАШ-ПОДДОМЕН.workers.dev`.

В файле `site/config.js` замените пустую строку на WSS-адрес **вашего собственного** Worker:

```javascript
window.ETS2_NAV_CONFIG = {
  relayUrl: 'wss://ets2-navigator-relay.ВАШ-ПОДДОМЕН.workers.dev'
};
```

Закоммитьте изменение — GitHub Pages обновится автоматически. Вместо изменения файла можно ввести адрес WSS в «Настройки сервера» на сайте: браузер запомнит его локально на этом устройстве.

Cloudflare Durable Objects доступны на поддерживаемых тарифах, включая бесплатные квоты SQLite-backed Durable Objects, но проверьте актуальные лимиты и условия аккаунта. Данный Worker не хранит данные или Steam-профили в постоянной базе.

## Шаг 4: поставить официальный мост данных телеметрии

Нужен работающий в ETS2 плагин, который выдаёт данные через `http://127.0.0.1:38471/stream`.

Пример — открытый проект [UncappingBadger / Badgers-SCS-Telemetry-Hub](https://github.com/UncappingBadger/Badgers-SCS-Telemetry-Hub). Его документация объясняет сборку DLL и размещение в:

```text
<папка ETS2>/bin/win_x64/plugins/scs_telemetry_hub.dll
```

Сам DLL сюда **не включён**. Установите/соберите плагин по его собственным инструкциям. Затем запустите игру. В браузере на игровом компьютере адрес `http://127.0.0.1:38471/snapshot` должен вернуть JSON при работающем плагине. Если не возвращает, мост запустить пока не получится.

## Шаг 5: подключение на сайте

Установите Python-библиотеку и запустите наш мост на ПК с ETS2:

```powershell
py -m pip install -r client/requirements.txt
py client/bridge.py --relay wss://ets2-navigator-relay.ВАШ-ПОДДОМЕН.workers.dev
```

В терминале появится **КОД СЕАНСА** из 12 символов. Откройте сайт на телефоне, введите этот код и нажмите «Подключить». Скорость и X/Z поступят в браузер. Игра и компьютер должны оставаться включёнными; при закрытии терминала трансляция остановится.

### Проверка без ETS2

Можно проверить весь сетевой канал, ещё не устанавливая игровой плагин:

```powershell
py client/bridge.py --relay wss://ets2-navigator-relay.ВАШ-ПОДДОМЕН.workers.dev --demo
```

Это **искусственные** данные. Скорость и координаты на сайте начнут обновляться. Маркер грузовика пока не рисуется на демонстрационном графе: настоящие игровые координаты нельзя достоверно совместить с вымышленной картой.

## Безопасность

- **Ник Steam не используется**: он не является ключом доступа к живой телеметрии.
- 12-символьный случайный код выступает секретом подключения (приблизительно 60 бит энтропии). Не публикуйте его и не показывайте посторонним в трансляциях.
- Передача идёт через TLS (`wss://`). Реле получает только X/Z, скорость, направление и название игры. Никаких паролей, Steam-токенов или данных браузера не требуется.
- Для каждой игровой сессии генерируется новый код, если не указан `--code`.
- Данный MVP не предназначен для публичной массовой эксплуатации: в нём нет полноценной системы аккаунтов, rate limiting, защит от злоупотреблений и ограничений времени жизни комнат. Для публикации общедоступного сервиса эти функции надо добавить.

## Следующий этап: настоящая карта ETS2

Сейчас `site/data/map.json` содержит **вымышленные** точки с `coordinateSystem: "demo"`. В ETS2 мир использует собственные координаты X/Z. Для достоверного навигатора потребуется:

1. Извлечь дорожную сеть и координаты городов из своей законной установки игры. В качестве основы изучить [truckermudgeon/maps](https://github.com/truckermudgeon/maps): parser, generator, маршрутизацию и PMTiles.
2. Получить данные и преобразовать их в формат приложения. Дороги ETS2 не равны дорогам OpenStreetMap и не совпадают с обычными GPS-координатами.
3. Добавить подложку настоящей карты в MapLibre/PMTiles и быстрый роутинг по полноценному графу. Простейший алгоритм Дейкстры из v0.1 пригоден только для небольшого графа, не всей карты игры.
4. Для точного позиционирования грузовика применять **те же координаты**, что и в Telemetry SDK, и учитывать дополнения карты/ProMods.
5. Не публиковать исходные ресурсы игры или производные тайлы без проверки прав и разрешений правообладателя. Можно генерировать тайлы из локально установленной копии игры и хранить отдельно при соблюдении условий использования.

Эта версия — честный **технический фундамент**, а не готовый GPS с дорогами и направлениями поворота. Отображение точного маршрута и реальных дорог в ETS2 будет реализовано отдельным этапом.
